# PDF 书签工作台使用指南

这是一个用于制作 PDF 目录书签的本地 Web 工作台。它以 JSON 管理项目的目录
（TOC, Table of Contents），在 Monaco 编辑器旁展示 PDF 预览，并可通过兼容
OpenAI 接口的视觉语言模型（VLM）从书籍自带的印刷目录页中提取目录结构。

## 功能概览

- **项目管理**：导入一个或多个 PDF，在项目库中管理文件，并为每个项目保存生成所需的元信息。
- **工作区编辑器**：每个项目可维护多个 TOC JSON 文件，支持实时 JSON 校验与自动保存。
- **预览与写入**：校验当前 TOC，并将书签写回项目 PDF。
- **AI 生成**：使用已配置的 VLM 扫描印刷目录页，生成 TOC JSON 文件。
- **Prompt Playground**：使用指定 VLM API 测试 prompt，并可插入后端渲染的 PDF 页图像。
- **任务队列**：查看后台生成任务的状态、进度、失败原因及生成结果操作。

## 快速开始

1. 在项目根目录启动应用：

   ```bash
   ./bookmark
   ```

   启动器会在首次运行时构建前端，将 API 与 Web UI 通过同一端口提供服务
   （默认 `http://127.0.0.1:8000`），并自动打开浏览器。更多启动参数见
   `README.md`，例如 `--port` 与 `--no-open`。

2. 在 **Projects** 页面上传一个或多个 PDF。
3. 如需使用 AI 生成，请在 **Settings** 中配置并测试至少一个兼容 OpenAI 接口的 VLM API。
4. 在加入生成队列前，为项目配置必要的生成元信息：目录页范围、页码偏移量与 VLM API。

默认情况下，项目数据保存在 `server/workspace_data/`，包括 PDF、TOC 文件、项目元信息、任务记录与生成缓存。
如需修改位置，可设置 `BOOKMARK_WORKSPACE_DATA` 环境变量。

## 项目页面

**Projects** 页面是项目级操作的主要入口。

- **导入**：将 PDF 拖入上传区域，或使用文件选择器上传。支持一次上传多个 PDF；每个 PDF 会分别创建为独立项目，失败信息按文件展示。
- **打开**：点击项目行进入对应工作区。
- **配置生成参数**：通过项目行右侧的更多菜单设置目录页范围、页码偏移量与 VLM API。
- **多选**：将光标移至项目行左侧附近会显示选择框。选择一个或多个项目后，可使用底部选择栏执行批量操作。
- **加入队列**：按各项目保存的元信息，将选中项目加入 AI 生成队列。
- **下载 PDF**：下载当前已写入书签的项目 PDF，文件名格式为 `<name>_bookmarked.pdf`。
- **删除**：确认后删除项目及其关联文件。

每个项目会保存以下元信息：

| 字段              | 含义                                                   |
| ----------------- | ------------------------------------------------------ |
| `page_offset`     | 将 TOC 中的相对页码映射到真实 PDF 页码时使用的偏移量。 |
| `toc_start`       | 印刷目录的起始页，使用从 1 开始的 PDF 绝对页码。       |
| `toc_end`         | 印刷目录的结束页，使用从 1 开始的 PDF 绝对页码。       |
| `provider_id`     | 项目加入生成队列时使用的 VLM API。                     |
| `inject_toc_page` | 预览写入时是否自动插入一个指向目录页本身的书签。       |

### 页码偏移量与目录页范围

应用中涉及两套页码：

- **PDF 页码**：PDF 文件中的物理页序号，从 1 开始计数。
- **印刷页码**：书籍正文中实际印刷出来、供读者引用的页码。

对于 `attribute: "relative"` 的 TOC 条目，应用使用以下规则计算目标页：

```text
PDF 页码 = 印刷页码 + page_offset
```

例如，如果书籍正文印刷第 `1` 页位于 PDF 第 `28` 页，则 `page_offset` 应设置为 `27`。
如果印刷页码与 PDF 页码一致，则设置为 `0`。当印刷页码大于 PDF 物理页序号时，偏移量也可以为负数。

`toc_start` 与 `toc_end` 始终使用从 1 开始的 PDF 绝对页码，并构成闭区间。它们用于指定 VLM 需要扫描的印刷目录页，
不是章节条目中引用的正文逻辑页码。

## 工作区编辑器

工作区左侧显示当前 TOC JSON 文件，右侧显示 PDF 预览，中间分隔栏可拖拽调整宽度。

- **TOC 文件**：一个项目可以包含多个 TOC JSON 文件。通过编辑器工具栏中的文件浏览器按钮切换文件；系统会按项目记住上次打开的文件。
- **自动保存**：编辑器内容会在输入后短暂防抖并自动保存。页码偏移量、目录范围等项目元信息独立保存。
- **实时校验**：编辑器使用与后端一致的 TOC JSON 结构进行校验，并在编辑时提示格式错误。
- **键盘快捷键**：Monaco 编辑器已启用常用编辑功能，支持接近 VS Code 的编辑快捷键。
- **预览操作**：点击 **Preview** 校验并写入当前 TOC；点击下载按钮导出当前已写入书签的 PDF。

## 预览与写入

**Preview** 会校验当前选中的 TOC JSON 文件，将目录书签写入 PDF，并用生成后的书签版文件替换项目的 `document.pdf`。
随后，右侧预览区域会重新加载更新后的 PDF。

- 无效 JSON、无效 TOC 结构以及偏移后超出 PDF 范围的页码，都会在写入前被拒绝。
- 如果写入失败，系统会保留上一次成功生成的 PDF。
- 点击 **Preview** 按钮旁的箭头可打开预览设置：
  - **Page offset**：解析 `relative` TOC 页码时使用的偏移量。
  - **Inject ToC page**：启用后，系统会自动在顶层插入一个指向 `toc_start` 的书签。若 TOC 标题以中日韩字符为主，标题为 `目录`；否则为 `Contents`。该书签使用 `attribute: "absolute"`，可重复执行且不会重复插入，并会持久化回正在写入的 TOC 文件。

## AI 生成

AI 生成可从两个入口启动：

- 在 **Projects** 页面配置一个或多个项目后，点击 **Add to queue** 加入队列；
- 在工作区工具栏中点击 **AI Generate**，为当前项目启动生成。

生成前需要满足以下条件：

- 已配置并通过测试的 VLM API；
- 有效的 `toc_start` / `toc_end` 目录页范围；
- 有效的 `page_offset`。

生成时，目录范围内的每一页都会以 220 DPI 渲染并发送给 VLM。模型对每一页返回扁平目录条目列表。
随后服务端会将这些条目组装为嵌套 TOC 树，执行一次层级修正，保存为生成型 TOC 文件，并尝试自动应用到项目 PDF。

- **自动应用**：生成成功后会自动写入项目 PDF。若 TOC 已生成但写入失败，任务会标记为失败，并显示类似
  `TOC generated but applying failed` 的信息；此时仍可打开生成的 TOC 文件进行检查和手动修正。
- **缓存**：逐页 VLM 响应与最终 TOC 会缓存到 `workspace_data/cache/`。缓存键包含 PDF、页码范围、模型、DPI 与渲染后的 prompt。
  对同一输入重复执行会更快；修改 prompt 会使相关缓存失效。

## Prompt

页面扫描 prompt 可在 **Settings → Prompt** 中自定义，最多 20,000 字符。请求发送前会替换以下占位符：

| 占位符        | 含义                          |
| ------------- | ----------------------------- |
| `{toc_start}` | 目录范围的起始页，从 1 开始。 |
| `{toc_end}`   | 目录范围的结束页，从 1 开始。 |
| `{pdf_name}`  | 不含扩展名的 PDF 文件名。     |

默认 prompt 要求模型遵守以下规则：

1. 只返回扁平数组，不要嵌套目录项。
2. 合并跨行标题，并移除类似 `Chapter 1.......10` 的引导点。
3. 只处理当前扫描页中可见的目录内容。
4. 忽略页眉、页脚、装饰元素以及非目录内容。
5. 保留标题中的原始编号，例如 `1.2.3` 或 `Appendix A`。
6. 使用 `indent` 返回视觉缩进层级，其中 `0` 表示顶层。
7. 将印刷页码原样复制为字符串。罗马数字或无法解析的页码会被读取器丢弃。
8. 对没有可见页码的标题，尽可能继承同一章节内后续第一个条目的页码。

模型必须只返回 JSON 数组：

```json
[{ "text": "Full Title String", "page": "12", "indent": 0 }]
```

## Prompt Playground

使用 **Playground** 可以在不启动完整生成任务的情况下调试目录提取 prompt。

- 选择已通过测试的 VLM API 与项目 PDF。
- 按页码插入 PDF 页面图像。图像由后端以 220 DPI 渲染，使用与 AI 生成一致的 PyMuPDF 路径。
- 点击 **Inject prompt into chat** 将当前 playground prompt 注入聊天框，可继续编辑后再发送。服务端只发送聊天框中可见的文本。
- 聊天会话由后端保存，并在再次打开 Playground 时恢复。模型请求只包含当前用户消息和本次附带的图像，不会把历史对话作为上下文发送。
- 点击聊天历史中的图像可以预览大图。
- 将当前 playground 中的 prompt 保存为全局页面扫描 prompt。

发送页面图像时，服务端会重新渲染同一项目页，并校验其 SHA-256 哈希后再转发请求。
如果 PDF 或渲染结果已变化，请求会被拒绝，需重新插入页面。这样可以保证 playground 实验与正式生成流程具备可复现性。

## 设置

- **VLM APIs**：管理兼容 OpenAI 接口的 VLM 服务。每个 API 包含名称、base URL、模型与 API key。列表中仅展示 API 名称，打开后可编辑连接详情。
- **测试 API**：后端会向该 API 发送一张很小的合成图片，并要求模型准确返回 `VLM_OK`。只有通过测试的 API 才可用于生成。
- **Prompt**：编辑全局页面扫描 prompt。点击 **Restore default** 可恢复内置默认 prompt。
- **Inject ToC page**：这是项目级选项，可在工作区预览设置中配置。

## TOC JSON 格式

TOC 是一个 JSON 数组。每个节点必须是对象，并符合以下结构：

| 字段        | 类型                         | 是否必需 | 说明                                                                             |
| ----------- | ---------------------------- | -------- | -------------------------------------------------------------------------------- |
| `title`     | string                       | 是       | 书签标题；空字符串无效。                                                         |
| `page`      | number \| `null`             | 是       | `relative` 条目的印刷页码、`absolute` 条目的 PDF 页码，或用于标题节点的 `null`。 |
| `attribute` | `"relative"` \| `"absolute"` | 否       | `page` 的解释方式；省略时默认为 `"relative"`。                                   |
| `children`  | array                        | 是       | 子书签列表；叶子节点使用 `[]`。                                                  |

页码解析规则：

- `relative`：使用 `page + page_offset` 得到从 1 开始的 PDF 页码。
- `absolute`：`page` 已经是从 1 开始的 PDF 页码，忽略 `page_offset`。
- `page: null`：用于仅作分组的标题节点。后端会优先从第一个带页码的子节点推断目标页；必要时也会尝试使用后续兄弟节点的目标页。

示例：

```json
[
  {
    "title": "Part I",
    "page": null,
    "children": [
      {
        "title": "Chapter 1",
        "page": 1,
        "children": [
          {
            "title": "Introduction",
            "page": 1,
            "children": []
          },
          {
            "title": "Background",
            "page": 4,
            "children": []
          }
        ]
      }
    ]
  },
  {
    "title": "Contents",
    "page": 3,
    "attribute": "absolute",
    "children": []
  }
]
```

## 任务页面

**Tasks** 页面展示所有项目的生成任务。

- **状态**：`queued`、`running`、`succeeded` 或 `failed`。
- **进度**：任务运行时，进度条会展示渲染、扫描、缓存读取、处理与保存等阶段。
- **筛选**：支持 All / Active / Succeeded / Failed。
- **操作**：可打开关联项目。对于成功任务，如果任务记录仍指向可用项目，也可以应用或下载生成结果。
